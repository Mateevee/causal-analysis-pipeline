# Causal discovery in multivariate time series: pipeline and benchmark

This repository contains the code behind the paper *An Intelligent
Multistage Pipeline for Causal Discovery and Effect Quantification in
Multivariate Time Series*: the proposed pipeline (the Causal Analysis
Pipeline, called `patch` in the code), the baselines it is compared with,
the loaders for every benchmark dataset, and the scripts that run and score
each experiment.

Every result in the paper comes from a run of one of the entry points listed
under [Reproducing the paper](#reproducing-the-paper). None of them takes
command-line arguments: the settings are constants in `Config/` or in the
"EXECUTION CONTROL" section of each script.

## Repository layout

| Folder / file | Contents |
|---|---|
| `Pipeline/` | The proposed pipeline, one file per stage. `Pipeline/README.md` maps each stage of the paper's pipeline figure to its file. |
| `ModelComparison/` | One wrapper per baseline: PCMCI, PCMCI+, PCMCI-GPDC, PCMCI+-GPDC, VARLiNGAM, DYNOTEARS, CUTS+, Granger, Transfer Entropy. |
| `Data/` | One loader or generator per benchmark. `Data/README.md` explains how to obtain every dataset. |
| `Config/execution.py` | The configuration of the main run: active datasets, models, baseline hyper-parameters and the pipeline's `PIPELINE_CONFIG`. |
| `Config/sensitivity.py` | The protocol of the sensitivity analysis (grids, joint draw, robustness criterion). |
| `Validation/` | Export of false positives and false negatives per model. |
| `Auxiliary/` | Post-hoc analyses that read an existing run (ranking metrics, majority vote, seed replication, summary tables). |
| `generators/` | The scripts that write every number, table and figure of the paper from finished runs (see `generators/README.md`). |
| `analysis/` | Follow-up analyses of the paper's results, each with its scripts, its results and a description (see `analysis/README.md`). |
| `main*.py`, `ablation_fusion.py` | Entry points (see below). |

## Installation

Python 3.12 is the version used for the paper.

```
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS
pip install -r requirements.txt
```

`torch` is only needed by the CUTS+ baseline (and once, to convert the DREAM3
files). If it fails to install or load on your machine, remove `cuts_plus` and
`cuts_plus_tau10` from `ACTIVE_MODEL_NAMES` in `Config/execution.py`; the
module is then not imported and the other models run normally.

The pipeline runs its permutation tests in parallel, with up to 20 workers
and 2 cores left free (`n_jobs` in `PIPELINE_CONFIG`, `Config/execution.py`).
The random seeds are set inside each task, so the number of workers does not
change the results.

## Data

The synthetic benchmarks (linear VAR, tigramite SCMs, Lorenz-96, coupled
logistic maps) are generated by the code. Some third-party datasets are
downloaded automatically on the first run. CausalTime, NetSim, Sachs, TEP,
BEELINE and Causal Chambers have to be downloaded by hand before running.

**[Data/README.md](Data/README.md)** has the download commands, the expected
folder layout and which entry point needs which dataset.

A dataset that cannot be loaded is skipped with a
`[WARNING] scenario source '<name>' could not be loaded` message, and the run
continues without it. Check the console for this warning before trusting a
run.

## Reproducing the paper

Run every script from the repository root.

| Script | What it runs | Output folder |
|---|---|---|
| `python main.py` | Main comparison on the development suite (the 51 scenarios marked D in Table 2 of the paper): the pipeline and every baseline at tau = 24 and tau = 10, on synthetic VAR, tigramite SCMs, Lorenz-96, logistic maps, CausalTime, ALARM and NetSim. | `Results/Run_<timestamp>/` |
| `python main_heldout.py` | The same models and configuration on the held-out datasets (the 39 scenarios marked H in Table 2: Sachs, PeMS-BAY, Walker Circulation, PetShop, TEP, BEELINE, Causal Chambers, DREAM3, EasyVista, RCAEval). Reported apart from the development suite. | `Results_HeldOut/Run_<timestamp>/` |
| `python main_gpdc.py` | The non-linear baselines PCMCI-GPDC and PCMCI+-GPDC, on the 36 scenarios where they are feasible. Kept separate because GPDC is by far the slowest part. | `Results_GPDC/Run_<timestamp>/` |
| `python main_ablation_patch.py` | Ablation of the pipeline: steps 1–6 add one component at a time, step 7 is the full pipeline, steps 8–10 remove one component each from it. | `Results_Ablation/` |
| `python main_sensitivity.py` | Sensitivity of the pipeline to its own cut-offs (one at a time and Latin hypercube). Protocol in `Config/sensitivity.py`. Resumable. | `Results_Sensitivity/Run_<timestamp>/` |
| `python main_seed_replication.py` | New random seeds for the four synthetic generators (160 scenarios), to check that the synthetic results do not depend on the specific realizations. Resumable. | `Results_Seeds/...` |
| `python main_pcmci_nobh.py` | PCMCI without the FDR-BH correction, as in Runge et al. (2019). | `Results_PCMCI_NoBH/Run_<timestamp>/` |
| `python main_granger_te.py` | Granger and Transfer Entropy alone, the two tests the pipeline combines. | `Results_GrangerTE/Run_<timestamp>/` |

The scripts below read a finished run and do not re-run any model:

| Script | What it computes |
|---|---|
| `python Auxiliary/ranking_metrics.py <RUN_DIR>` | AUROC, AUPRC and SHD for every model. |
| `python Auxiliary/majority_vote.py <RUN_DIR>` | A majority vote of the baselines, scored as an extra model. |
| `python Auxiliary/seed_replication_analysis.py <RUN_DIR>` | Confidence intervals of the seed replication (also run at the end of `main_seed_replication.py`). |
| `python ablation_fusion.py <RUN_DIR> [OUT_DIR]` | Ablation of the evidence-fusion stage: alternative acceptance rules replayed on the pipeline's unfiltered output. |

The numbers, tables and figures of the paper are written from finished runs by
the scripts in [`generators/`](generators/README.md). They read the run of
`main.py`, the run of `main_heldout.py` and the runs of the separate
experiments from the origins set in `generators/origins.py`.

To run a single scenario instead of the whole suite (for example, to check the
installation or inspect the per-stage output), use
`python main_run_one_case.py`. It runs the tigramite `large_mixed` scenario
with 3 seeds and the models of `Config/execution.py`.

### Randomness

All random seeds are fixed in the code: the scenario seeds are listed in
`main.py` and `Config/execution.py`, and the pipeline's own seeds are literals
in its modules. Re-running a script with the same package versions produces
the same scenarios and the same decisions. `main_seed_replication.py` writes
the git commit, the Python version and the full model configuration to
`run_config.txt`.

## Output of a run

Every entry point writes one folder per scenario:

```
<OUTPUT_DIR>/<scenario>/
    source.csv              the input series
    ground_truth.csv        the true causal pairs (causal_gt column)
    scenario_params.txt     generator parameters (synthetic scenarios)
    validation_summary.csv / .txt   scores of every model on this scenario
    <model>/
        original.csv        every pair the model tested, before its decision
        results.csv         the pairs the model reports as causal
        time.txt            run time and status
        fp_errors.csv       false positives (full rows)
        fn_errors.csv       false negatives (rows from original.csv)
        cascade_log.txt/.json   per-pair decisions of the DML cascade (pipeline only)
```

`validation_summary.csv` holds TP, FP, FN, TN, precision, recall and F1 for
each model. At the end, `main.py` prints a report that consolidates them over
all scenarios (`Auxiliary/consolidate_summaries.py`). By default, pairs are
scored at the entity level and are directional (A -> B and B -> A are
different pairs). Both choices are set in `Config/execution.py`
(`USE_CANONICAL_PAIR`, `DETECT_INTRA_ENTITY`) and can be changed without
re-running the models.

If a model fails on a scenario, the run continues and a diagnostic file is
written to `ModelComparison/logs/failures/`.
